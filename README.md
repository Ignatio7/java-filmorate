# Filmorate

Бэкенд сервиса для работы с фильмами и пользователями: REST API, базовая валидация и хранение данных в памяти приложения.

## Стек

- **Java** 21  
- **Spring Boot** 3.5  
- **Maven** — сборка и зависимости  
- **Lombok** — сокращение шаблонного кода (`@Data`, `@FieldDefaults` и др.)  
- **Bean Validation** — проверка входящих данных  
- **SLF4J** (через Spring Boot) — логирование операций

## Требования

- JDK 21  
- установленный **Maven** 3.9+ (или свой способ сборки через IDE)

## Сборка и запуск

```bash
mvn clean package
mvn spring-boot:run
```

После запуска приложение слушает порт по умолчанию **8080** (можно переопределить в `application.properties`).

Запуск тестов:

```bash
mvn test
```

## API

Базовый URL: `http://localhost:8080`

### Фильмы (`/films`)

| Метод | Путь       | Описание              |
|-------|------------|------------------------|
| GET   | `/films`   | Список всех фильмов   |
| POST  | `/films`   | Добавить фильм        |
| PUT   | `/films`   | Обновить фильм        |

Тело запроса (JSON) — поля модели фильма:

- `name` — название (не пустое)  
- `description` — описание (не длиннее 200 символов)  
- `releaseDate` — дата релиза (не раньше 28.12.1895)  
- `duration` — длительность в минутах (строго положительное число)  

При создании `id` присваивается сервером. При обновлении в теле передаётся существующий `id`; при неизвестном `id` возвращается ошибка **404**.

### Пользователи (`/users`)

| Метод | Путь       | Описание                 |
|-------|------------|---------------------------|
| GET   | `/users`   | Список всех пользователей |
| POST  | `/users`   | Создать пользователя     |
| PUT   | `/users`   | Обновить пользователя    |

Тело запроса (JSON):

- `email` — непустая строка и корректный email  
- `login` — непустой, без пробелов  
- `name` — необязательно; если пусто или не указано, подставляется `login`  
- `birthday` — не в будущем  

Идентификатор задаётся при создании; при обновлении несуществующего пользователя — **404**.

### Ошибки валидации

При ошибках проверки тела запроса возвращается ответ с описанием нарушений (через `GlobalExceptionHandler`).
