# Filmorate

Бэкенд сервиса для работы с фильмами и пользователями: REST API, валидация, хранение данных в памяти, лайки фильмам и социальные связи между пользователями.

## Стек

- **Java** 21
- **Spring Boot** 3.5
- **Maven** — сборка и зависимости
- **Lombok** — сокращение шаблонного кода (`@Data`, `@FieldDefaults` и др.)
- **Bean Validation** — проверка входящих данных
- **SLF4J** (через Spring Boot) — логирование операций

## Требования

- JDK 21
- Maven 3.9+

## Сборка и запуск

```bash
mvn clean package
mvn spring-boot:run
```

После запуска приложение слушает порт **8080** (можно переопределить в `application.properties`).

Запуск тестов:

```bash
mvn test
```

## API

Базовый URL: `http://localhost:8080`

### Фильмы (`/films`)

| Метод  | Путь                          | Описание                                          |
|--------|-------------------------------|---------------------------------------------------|
| GET    | `/films`                      | Список всех фильмов                               |
| POST   | `/films`                      | Добавить фильм                                    |
| PUT    | `/films`                      | Обновить фильм                                    |
| GET    | `/films/{id}`                 | Получить фильм по ID                              |
| PUT    | `/films/{id}/like/{userId}`   | Поставить лайк фильму                             |
| DELETE | `/films/{id}/like/{userId}`   | Убрать лайк                                       |
| GET    | `/films/popular?count={n}`    | Топ-N фильмов по лайкам (по умолчанию — 10)      |

Тело запроса (JSON) при создании/обновлении:

- `name` — название (не пустое)
- `description` — описание (не длиннее 200 символов)
- `releaseDate` — дата релиза (не раньше 28.12.1895)
- `duration` — длительность в минутах (строго положительное число)

При создании `id` присваивается сервером. При обновлении в теле передаётся существующий `id`; при неизвестном `id` возвращается **404**.

### Пользователи (`/users`)

| Метод  | Путь                                   | Описание                          |
|--------|----------------------------------------|-----------------------------------|
| GET    | `/users`                               | Список всех пользователей         |
| POST   | `/users`                               | Создать пользователя              |
| PUT    | `/users`                               | Обновить пользователя             |
| GET    | `/users/{id}`                          | Получить пользователя по ID       |
| PUT    | `/users/{id}/friends/{friendId}`       | Добавить в друзья                 |
| DELETE | `/users/{id}/friends/{friendId}`       | Удалить из друзей                 |
| GET    | `/users/{id}/friends`                  | Список друзей пользователя        |
| GET    | `/users/{id}/friends/common/{otherId}` | Общие друзья двух пользователей   |

Тело запроса (JSON) при создании/обновлении:

- `email` — непустая строка, корректный email
- `login` — непустой, без пробелов
- `name` — необязательно; если пусто или не указано, подставляется `login`
- `birthday` — не в будущем

Идентификатор задаётся при создании; при обновлении несуществующего пользователя — **404**.

### Коды ошибок

| HTTP | Причина                                |
|------|----------------------------------------|
| 400  | Ошибка валидации тела запроса          |
| 404  | Сущность не найдена (неизвестный `id`) |
| 500  | Внутренняя ошибка сервера              |

## Архитектура

Приложение разделено на три слоя:

```
controller  →  service  →  storage
```

- **Controller** — принимает HTTP-запросы, делегирует бизнес-логику сервису.
- **Service** — реализует бизнес-логику (добавление друзей, лайки, рейтинг).
- **Storage** — интерфейс хранилища; текущая реализация — `InMemory` (данные в памяти JVM).
